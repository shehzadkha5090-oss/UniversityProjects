Preprocessing (Pipeline, fit on train only): numeric median-impute + StandardScaler;

Preprocessed features: 58 (15 numeric + 43 one-hot).
Polynomial expansion: PolynomialFeatures(degree=2, include_bias=False) on ALL
  preprocessed features: p = 58 + 58*59/2 = 1769 features.
  p > n: 1769 > 649 rows in total and > 486 training rows, but p is NOT 10,000,
  so this project does NOT claim 10,000 features.

Results (same split for every method):

Discussion — p>>n overfitting, honestly:
  Method (a), all 1769 features: train ROC-AUC = 1.0000 but test ROC-AUC = 0.9377 — a train-test gap of 0.0623.
  With p (1769) far above the 486 training rows, the L2 model can essentially
  memorise the training set (train ROC-AUC at/near 1.0) while generalising worse,
  which is exactly the p>>n failure mode: many more parameters than observations,
  so fitted coefficients are unstable and test performance drops.
  Selection helps here in the sense that methods (b), (c) and (d) use far fewer
  features, do not show the same train-test gap, and beat (a) on test ROC-AUC
  (0.9664 / 0.9649 / 0.9577 vs 0.9377) — though stability selection's test
  accuracy (0.8957) is below (a)'s (0.9202), so the gain is in ranking, not in
  every metric. Selection does NOT automatically beat the simpler 58-feature
  reference model (test ROC-AUC 0.9420): with only 486 training rows, the
  selected sets are themselves noisy, and a univariate or L1 screen can discard
  weak-but-jointly-useful signals. The L1/stability overlap is reassuring in one
  respect — all 13 stability-selected features are also L1-selected (Jaccard
  0.5909 only because the L1 set is larger, 22 vs 13) — but that stability is
  over bootstrap resamples of the same small training set, not over new data.
  The honest reading is that expansion to p=1769 bought no reliable gain
  over the 58-feature model on this small dataset; selection mainly recovered
  comparable-or-better test ROC-AUC with far fewer features, rather than
  transforming performance.
  No result here should be read as evidence about true 10,000+ feature settings,
  because that condition is not met (see CAVEAT above).
